# 16：对比原版 MPPI 基线

> **本步目标：** 在控制变量一致的条件下，对比原版 MPPI 与 MPPI + DynamicRiskCritic 的安全性、效率和实时性。
>
> **AI 会做什么：** 生成 benchmark 运行脚本、指标表、绘图和结论草稿。
>
> **你只需要做到：** 冻结地图、起终点、actor 轨迹和速度上限，保证对照只差 `DynamicRiskCritic`，并核对结论与原始数据一致。

在相同地图、目标、动态 actor 路线和重复次数下，对比原版 MPPI 与加入 DynamicRiskCritic 后的结果。

对比关注成功率、碰撞/近碰、最小距离、耗时、路径长度和不必要停顿，而不是只挑一段最好看的视频。

完成标准：有一张诚实说明改善和代价的对照表，为第 05 模块实验记录准备输入。

## 本步：AI 汇总与作图，你控制变量并核验结论

不新增 Critic 代码。让 AI 生成比较表、指标脚本、汇总和图表；你负责确认两组实验确实使用同一场景和判定规则，并核验结论与原始数据一致。这是把“功能能跑”升级为“项目可信”的最后一步。

## 固定不变的条件

```text
地图、机器人 footprint、起点、目标、actor 路线、actor 速度、最大速度、
prediction 参数、运行次数、成功/碰撞判定规则
```

唯一应变化的是 controller 配置：原版 MPPI 是否加入 `DynamicRiskCritic`。

## 结论必须同时包含收益和代价

好的结论格式是：

> 在固定横穿场景下，动态风险版将最小距离从 A 提高到 B，但平均完成时间增加 C；在窄通道场景中仍会出现 D，因此需要在第 05 模块继续调参与重复验证。

不要写“加入预测后导航效果明显更好”，除非数据真的支持，并且同时报告失败样本和代价。

## 推荐流程：先冻结实验，再开始跑

先让 AI 在实验日志最上方写下这些固定项，运行过程中不允许修改：

```text
地图文件和版本；机器人 radius；起点/目标；actor 初始位姿、路线、速度；
MPPI speed limits；prediction horizon；近碰阈值；每组重复次数。
```

然后采用交替顺序，而不是先连续跑完一组：

```text
baseline 第 1 次 → dynamic-risk 第 1 次
baseline 第 2 次 → dynamic-risk 第 2 次
……
```

这样能减少 Gazebo 初始状态、机器性能或偶发定位差异带来的偏差。

### 指标先定义再测量

让 AI 在首跑前写清：

- “到达”以 NavigateToPose action 成功还是目标距离阈值为准；
- “近碰”距离阈值是多少、距离来自 Gazebo 真值还是 LiDAR/Track 估计；
- “停顿”线速度低于多少、持续多久才算一次；
- 失败、超时、人工取消分别如何计入统计。

建议首先用 Gazebo 真值只做**离线评估标签**，绝不在控制链中订阅它。这样既能客观统计，也不破坏“算法不依赖真值”的原则。
