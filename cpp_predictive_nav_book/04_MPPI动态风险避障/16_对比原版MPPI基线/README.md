# 16：对比原版 MPPI 基线

> 本步目标：在控制变量一致时，对比原版 MPPI 与 MPPI + DynamicRiskCritic 的安全性、效率和实时性。

## 为什么视频不足以证明效果

一段成功避让视频可能只是 actor 恰好走得远、静态 costmap 已经看到了障碍，或某次定位更好。
要证明动态预测带来价值，唯一应变化的是是否启用 DynamicRiskCritic。

## 必须固定的条件

```text
地图和版本
机器人 footprint
起点、目标
actor 初始位姿、路线、速度、循环方式
MPPI 速度与加速度上限
prediction horizon 与参数
近碰阈值、超时规则、重复次数
```

推荐交替运行，而不是先把一组全部跑完：

```text
baseline 第 1 次 → dynamic-risk 第 1 次
baseline 第 2 次 → dynamic-risk 第 2 次
...
```

这能减少 Gazebo 初始状态和偶发定位差异带来的偏差。

## 最小结果表

| 指标 | 原版 MPPI | MPPI + DynamicRiskCritic | 说明 |
|---|---:|---:|---|
| 重复次数 |  |  | 不能只跑一次 |
| 到达率 |  |  | 成功 action / 总次数 |
| 碰撞/近碰次数 |  |  | 先定义距离阈值 |
| 最小动态距离 |  |  | m，说明测量来源 |
| 完成时间 |  |  | s |
| 路径长度 |  |  | m |
| 停顿次数/时长 |  |  | 防止无限等待 |
| 控制周期耗时 |  |  | 观察实时性代价 |

可以使用 Gazebo 真值做**离线评估标签**，但控制逻辑不能订阅真值；否则实验会破坏“只依赖
LiDAR 跟踪与预测”的项目边界。

## 结论应怎样写

好的结论同时包含收益与代价：

> 在固定横穿场景中，动态风险版提高了最小动态距离，但平均完成时间增加；在窄通道中仍
> 可能因候选全部不可行而停止，因此需要继续调参数或改进全局可通行性判断。

不要写“效果明显更好”，除非表格数据支持，且同时报告失败样本、耗时和不必要停顿。

## 本步完成标准

- [ ] 两组使用相同地图、目标、actor 轨迹和速度上限；
- [ ] 到达、近碰、停顿和失败的判定规则在首跑前写清；
- [ ] 保留原始日志/rosbag、汇总表和至少一张比较图；
- [ ] 结论同时说明收益、代价和失效场景；
- [ ] 不把 Gazebo 真值接入控制环。
