# 10：加入时间对齐与 TTC 风险

> 本步目标：在同一未来时刻比较机器人候选位置与障碍物预测位置，并计算可解释的近碰时间 TTC。

## 为什么数组下标不能直接对齐

当前 MPPI 使用：

```text
model_dt = 0.05 s
```

第三章 prediction 默认使用：

```text
time_offsets = 0.2, 0.4, ..., 2.0 s
```

所以 MPPI 的第 6 个候选点对应 `0.30 s`，prediction 没有恰好位于 `0.30 s` 的点。若只按
数组下标比较，就会把不同时间的位置当作同一时刻，风险判断不可靠。

## 怎样插值

当查询时刻位于 `t0` 和 `t1` 之间：

```text
alpha = (query_time - t0) / (t1 - t0)
value = (1 - alpha) × value0 + alpha × value1
```

例子：`0.2 s` 的 x 为 1，`0.4 s` 的 x 为 3，查询 `0.3 s` 时得到 x=2。
位置与协方差第一版都可使用同样的线性插值。

查询时刻早于第一个 prediction 点或晚于最后一个点时，返回“不可用”，而不是重复使用
最后一个点伪装成未来真值。

## TTC 是什么

TTC（Time To Collision）不是“当前已经撞上”，而是按相对运动估计两者多久后最接近。

```text
p = obstacle_position - robot_position
v = obstacle_velocity - robot_velocity

t_closest = -dot(p, v) / ||v||²
```

只有在相对速度足够大、两者正在靠近、`t_closest` 为正且位于关注 horizon 内时，才使用它。
障碍物远离、相对速度接近零或最近时刻已经过去时，不产生 TTC risk。

这是一种“最接近时刻”的近似，不是复杂几何模型下的精确碰撞时间；代码和实验结论都应
诚实说明这个边界。

## 必须通过的数值例子

| 场景 | 预期 |
|---|---|
| 障碍物远离机器人 | TTC 不存在 |
| 相向而行，距离 2 m，相对速度 1 m/s | TTC 约 2 s |
| 查询时间超过 prediction horizon | 插值结果不存在 |
| 位置相近但经过时间不同 | 不应被当作同一时刻碰撞 |

这些例子比只看 RViz 更能验证时间语义正确。
