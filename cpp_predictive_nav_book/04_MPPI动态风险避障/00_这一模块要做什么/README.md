# 00：这一模块要做什么

> 本步目标：在修改 C++ 或 YAML 前，先理解 prediction 怎样影响 MPPI 的局部动作；本步不运行新代码。

## 前三章完成了什么，还缺什么

前三章已经输出障碍物当前的位置、速度、协方差，以及未来 2 秒内一串可能位置。
这些信息通过 ROS topic 发布，但只是“信息”，机器人还不知道应怎样据此选速度。

```text
Track:       目标现在在哪里、朝哪边运动、估计是否可靠
Prediction:  目标在 0.2 / 0.4 / ... / 2.0 s 后可能在哪里
```

机器人还必须回答：如果我选择某个速度，障碍物也按预测运动，未来会不会相遇？
这一章的 Critic 就是回答这个问题的地方。

## MPPI 在控制周期里做什么

```text
当前机器人状态 + 当前全局路径
          ↓
采样许多符合差速底盘约束的控制序列
          ↓
前向模拟为许多候选机器人轨迹
          ↓
多个 Critic 分别给每条候选轨迹打分
          ↓
选择总代价较低的一个，发布下一条 /cmd_vel
```

原版 Critic 已关心路径贴合、静态障碍、目标朝向与速度约束；
`DynamicRiskCritic` 只新增未来动态障碍物风险。

## 为什么不能直接让 prediction 发布速度

prediction 节点知道障碍物状态，却不知道机器人目标、静态地图、底盘约束和其他 Critic。
若它自己发布 `/cmd_vel`，会和 MPPI 争夺同一个控制话题。

```text
prediction_node：发布“障碍物可能怎样运动”
DynamicRiskCritic：把这份信息转成候选轨迹 cost
MPPI：综合全部 cost 后唯一地选择速度
scan_safety_guard：继续提供当前 scan 的外层安全底线
```

## 一个时间对齐例子

机器人和方块都可能经过走廊中心 `(0, 0)`：

| 情况 | 机器人经过时间 | 方块经过时间 | 是否天然冲突 |
|---|---:|---:|---|
| A | 1.0 s | 1.0 s | 高风险 |
| B | 1.0 s | 3.0 s | 不必然冲突 |

所以本章不只计算当前距离，而要比较同一未来时刻的机器人候选位置和障碍物预测位置。

## 本章最终的方法

```text
r_i(t_k)        第 i 条机器人候选轨迹在 t_k 的位置
o_j(t_k)        第 j 个障碍物在 t_k 的预测位置
Σ_j(t_k)        该预测位置的不确定性
                ↓
distance / TTC / uncertainty risk
                ↓
data.costs(i) += dynamic_risk_cost
```

`+=` 表示动态 Critic 只能累加自己的代价，不能清空或覆盖其他 Critic 的分数。
