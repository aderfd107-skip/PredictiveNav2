# 00：这一模块要做什么

## 这一章终于要解决什么

前三章完成的是一条“看见并理解障碍物”的链路：

```text
2D LiDAR → cluster → Track（当前位置、速度、协方差）
         → prediction（未来位置、未来协方差）
```

但到第三章为止，机器人仍然**不会因为预测结果而改变运动**。RViz 里的青色线和紫色椭圆只是人能看见；Nav2 的局部控制器还没有读取它们。

第四章要补上最后一段决策链路：

```text
/dynamic_obstacles/predictions
              ↓
DynamicRiskCritic：给每条机器人候选轨迹计算动态风险分
              ↓
Nav2 MPPI：综合所有分数，选出当前最合适的局部运动
              ↓
/cmd_vel → scan_safety_guard（额外底线）→ Gazebo / 真实底盘
```

换句话说，本章要让机器人不只判断“**障碍物此刻离我近不近**”，而是判断：

> 如果我选择这条速度轨迹，同时障碍物也按预测轨迹运动，我们会不会在**同一时刻**靠得太近？

这才是本项目“预测感知动态避障”的关键闭环。

## 一个具体例子

设机器人计划 1 秒后经过走廊中央；动态方块现在还在旁边，但预测显示它也会在 1 秒后穿过走廊中央。

- 只看当前 LiDAR/costmap：方块现在离得远，候选轨迹可能仍被认为安全；
- 本章的动态风险：机器人轨迹与障碍物轨迹在 `t=1.0 s` 空间接近，因此该候选会得到高风险分；
- MPPI 综合路径跟随、静态障碍、平滑性、控制代价和这条动态风险后，可能选择减速等待，或选择另一条局部绕行轨迹；
- 最终 `/cmd_vel` 仍由 Nav2 MPPI 统一发布，不会被我们的插件绕开。

注意：Critic 不是“见到人就急停”的独立安全节点。它提供的是连续的风险偏好；真正的静态碰撞检查、运动学约束、Nav2 恢复行为，以及已有 scan safety guard 都仍然保留。

## MPPI 到底在做什么

可以把 MPPI 暂时理解为一个每个控制周期都运行的小型“试驾比赛”。它会从机器人当前状态出发，生成许多符合差速底盘约束的短时间候选控制序列，并向前模拟得到许多机器人候选轨迹。

```text
当前机器人状态 + 当前全局路径
              ↓
产生很多候选控制 / 候选机器人轨迹
              ↓
每个 Critic 分别评分
  静态障碍、路径贴合、朝向、平滑性、速度控制、动态风险……
              ↓
各项 cost 相加，低风险/低代价的候选更受偏好
              ↓
MPPI 选出当前控制命令，下一周期再重新计算
```

严格地说，MPPI 会对上一时刻较优控制施加高斯扰动、前向仿真并由各 Critic 的 cost 进行加权优化；你现阶段先抓住三件事即可：

1. MPPI 比较的是**一批候选轨迹**，不是直接对一条全局路径发速度；
2. Critic 是一个独立、可插拔的评分规则；
3. 我们只增加动态风险 cost，不重写 MPPI，也不自己直接发布 `/cmd_vel`。

Nav2 官方把 MPPI 定义为基于采样、可用模块化 Critic 扩展目标函数的预测控制器；其 Controller Server 负责承载并调用所配置的控制插件。[MPPI Controller 文档](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/controller_plugins/mppi_controller/configuring_mppic/) [Controller Server 文档](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/controller_server/)

## 本项目会实现什么方法

本项目的方法可以暂时命名为：

> **基于预测轨迹、时间对齐和不确定性约束的 MPPI 动态风险 Critic**

它不是一篇宣称提出全新 MPPI 数学理论的论文算法，而是一个有明确工程边界的 Nav2 扩展：将本项目自己从 LiDAR 得到的跟踪/预测结果，以正确的方式接入原生 MPPI 的候选轨迹评分过程。

对于一条 MPPI 候选机器人轨迹，在其每个离散时刻 `t_k`：

```text
机器人候选位置 r(t_k)
障碍物预测位置 o_i(t_k)
预测不确定性 Σ_i(t_k)
            ↓ 同一时刻对齐
距离 d_i,k = || r(t_k) - o_i(t_k) ||
            ↓ 结合机器人尺寸、障碍物尺寸、安全裕量、不确定性
dynamic_risk_i,k
            ↓ 对所有障碍物和全部时间点累加
DynamicRiskCritic cost
```

第一版会按由浅到深的顺序实现：

1. 先让原版 MPPI 在同一场景稳定工作，作为没有动态预测的 baseline；
2. 创建能被 Nav2 加载、但初始不改变任何 cost 的空 Critic；
3. 缓存最新的 `/dynamic_obstacles/predictions`；
4. 验证 prediction 的时间戳、`odom` 坐标系和有限数值；
5. 先仅按时刻对齐计算机器人候选点到障碍物预测点的距离风险；
6. 再加入 TTC（Time To Collision）和协方差带来的安全裕量；
7. 把风险写进 MPPI cost，并与原版 MPPI 做同场景对照。

这条顺序很重要：如果一开始把距离、TTC、协方差、插件加载和参数调优混在一起，出现“车不走/绕不过去”时根本无法判断是哪个环节错了。

## 为什么本项目选 MPPI + 自定义 Critic

它有四个关键特点。

### 1. 风险与机器人候选动作在时间上对齐

不是把未来障碍物位置粗暴投到当前 costmap，而是比较 `r(t_k)` 与 `o(t_k)`。这能表达“空间位置相同但经过时间不同，未必相撞”和“现在离得远但未来会相遇”的区别。

### 2. 使用不确定性，而不是把预测当真值

第三章输出的不只有预测中心线，还有位置协方差。第四章会把较大的预测不确定性转换为更保守的安全半径或风险权重。

因此它不会说“障碍物一定在这里”，而是说“障碍物越不确定，这条靠得很近的候选轨迹越不值得选择”。这比只按预测中心点硬碰硬更符合真实传感器系统。

### 3. 以插件方式嵌入成熟导航栈

本项目只负责一个 Critic，不代替 MPPI 原有的路径跟随、静态障碍、速度约束和恢复机制。Nav2 的控制器本身就是通过插件组合能力的；MPPI 的 Critic 也正是官方预留的扩展点。[Nav2 插件与控制器说明](https://docs.nav2.org/jazzy/configuration_and_development/first_time_robot_setup_guide/navigation_plugins/setup_navigation_plugins/)

这使项目比“监听预测后自己随手发 `/cmd_vel`”更有工程价值：接口清晰、能做消融对比、也更容易迁移到真实底盘。

### 4. 有可证明的 baseline

先比较原版 MPPI，再只加入 DynamicRiskCritic。第五章会固定地图、起终点、动态 actor 轨迹和速度上限，统计到达率、最小距离、碰撞/近碰、耗时和舒适性。

所以本项目要证明的不是“视频里它有一次绕开了”，而是“在相同条件下，预测风险信息是否稳定改善了局部决策”。

## 达到类似动态避障效果的其他方法

“提前躲开动态障碍物”并不只有一种做法。以下方法的目标相近，但信息利用方式和工程代价不同。

| 方法 | 主要思路 | 优点 | 局限 | 与本项目的关系 |
|---|---|---|---|---|
| 当前 costmap / DWB | 把 LiDAR 当前看到的障碍写进局部代价地图，采样速度并避开 | 已有 Nav2 支持，部署简单 | 主要看当前占据，难明确处理未来相遇时刻 | 是现有 DWB baseline，不是本项目的动态预测方案 |
| 时空膨胀 costmap | 将预测位置在未来多个时刻投影为一串代价区域 | 直观，可复用 costmap 思想 | 时空层管理复杂，可能把未来障碍物“糊”得过于保守 | 可以作为未来替代/对照实现 |
| 速度障碍 VO / ORCA | 在速度空间排除会发生碰撞的相对速度 | 对多移动体交互有清晰几何解释，反应快 | 常需假设对方会协作或运动模型可信；和全局路径、复杂底盘约束结合要额外设计 | 适合做对比阅读，不作为本项目主线 |
| TEB | 优化带时间维度的弹性轨迹，同时处理障碍和运动学 | 时间显式在优化变量中，动态场景表达自然 | 参数、优化收敛和工程集成复杂；需要另一套控制器工作流 | 是 MPPI 的可替代局部控制器，不是当前插件方案 |
| 完整非线性 MPC | 直接构造约束优化：状态、控制、动态障碍、预测都写入优化问题 | 数学表达强，可加入复杂约束 | 求解器、实时性、调参和故障处理成本高 | 适合更强研究型项目，当前阶段不必从零实现 |
| 学习式预测 + 策略/RL | 从数据学习人/车运动和避障策略 | 可捕捉复杂行为模式 | 需要数据、训练、泛化和安全验证；可解释性较弱 | 可替换第三章预测器，但不应跳过安全与 benchmark |
| 外部急停/速度过滤 | 依据当前 scan 或距离直接限速、刹停 | 简单可靠，适合作最后防线 | 容易过晚、频繁急停，通常不会主动绕行 | 本项目已有 scan safety guard；它是安全底线，不是核心贡献 |

Nav2 也提供 DWB、MPPI、Regulated Pure Pursuit 等不同控制器选项；其中 DWB 以速度空间采样和 Critic 评分工作，MPPI 是可扩展目标函数的预测控制器。[Nav2 控制器选择说明](https://docs.nav2.org/rolling/configuration_and_development/tuning_guide/)

## 本项目的方法到底“特别”在哪里

要诚实地说：**CV + Kalman + MPPI Critic 这些单独的组件都不是新的。** 项目的价值不应该表述为“发明了一个前所未有的算法”。

它的特别之处在于系统级闭环与工程实现：

```text
廉价 2D LiDAR
  → 不依赖 Gazebo 真值的 cluster / 多目标跟踪
  → 带协方差的短期预测
  → 与 MPPI 候选机器人轨迹逐时刻对齐
  → 不确定性风险评分
  → Nav2 原生控制链输出速度
  → rosbag 与 baseline 支持可复现评估
```

这条链路把感知、估计、预测、规划、控制接口、调试和实验验证连接起来。对于求职项目，真正能体现水平的是：

- 你能解释每层输入输出和坐标/时间语义；
- 你知道预测坏了不能直接拿去控制，必须有新鲜度和质量门限；
- 你没有绕过 Nav2 安全链路，而是用 pluginlib 接入可维护的扩展点；
- 你能用原版 MPPI 与动态风险版的消融对比说明收益和代价；
- 你能明确 CV 在急转弯、遮挡和长期预测上的局限，而不是夸大效果。

## 接下来需要掌握的知识

不要求现在全部会。后续每一步只引入一小块。

| 知识 | 用在什么地方 | 现在先理解到什么程度 |
|---|---|---|
| 全局规划、局部规划、底盘控制的边界 | 明确本章属于局部规划/决策，不是电机控制 | 知道 global path 给大方向，MPPI 负责短时动作 |
| MPPI 的候选轨迹与 Critic | 理解风险分最终怎样影响 `/cmd_vel` | 知道 Critic 只加 cost，不直接控制 |
| ROS 2 lifecycle 与 Nav2 Controller Server | 启动、加载和诊断 MPPI | 能看懂 `active` 和 plugin load log |
| C++ 继承、虚函数、override | 实现 Nav2 Critic 基类 | 知道“基类规定接口，子类填风险逻辑” |
| pluginlib、XML、CMake 导出 | 让 Nav2 在运行时找到你的 `.so` 插件 | 知道插件不是普通 `ros2 run` 节点 |
| mutex 与快照缓存 | prediction 回调与控制循环并发访问数据 | 控制循环只读取一份快速快照，不能等待或阻塞 |
| 候选轨迹距离、机器人 footprint | 计算机器人和障碍物是否过近 | 先会二维欧氏距离，后面加入尺寸和安全半径 |
| 时间对齐、TTC | 判断是否会在相同未来时刻接近 | 先能说清“同一位置、不同时间不等于碰撞” |
| 协方差与保守风险 | 处理预测不可靠的情况 | 方差大 → 风险范围/安全裕量更大 |
| 参数调优与对照实验 | 防止权重靠感觉乱设 | 一次只改一项，与原版 MPPI 对照 |

## 本章的步骤安排

```text
01–03：先理解 MPPI，并建立、观察原版 MPPI baseline
04–06：创建、导出、加载一个空的 DynamicRiskCritic
07–08：安全地接收 prediction，检查时效/坐标系
09–11：距离 → 时间对齐/TTC → 动态风险 cost
12–14：配置、启用、观察减速/等待/绕行
15–16：排错、安全边界、与原版 MPPI 对比
```

在第 01 步之前，你只需记住一句话：

> 第三章回答“障碍物未来可能在哪里”；第四章回答“面对这些可能性，机器人现在该选哪条局部运动”。

## 本章完成后的验收标准

完成第四章后，应能证明以下事实：

- 原版 MPPI 可在同一地图和动态场景运行，作为 baseline；
- `DynamicRiskCritic` 被 Nav2 成功加载，且不直接发布 `/cmd_vel`；
- 插件只消费新鲜、`odom` 坐标系且数值有效的 prediction；
- 与预测障碍物在同一时刻接近的候选轨迹会得到更高动态风险 cost；
- 在相同场景中，MPPI + DynamicRiskCritic 能出现可解释的减速、等待或局部绕行；
- 能说明安全边界：预测失效时怎么处理、静态碰撞检查仍由谁负责、如何和原版 MPPI 做公平对照。

## 本章的手写学习规则

从第 04 步起，README 不再先给完整可复制的实现。每一步会提供要修改的文件、真实 Jazzy 头文件、函数签名、成员变量和验收命令；你先完成标记为“必须手写”的部分。

| 标记 | 含义 |
|---|---|
| **必须手写** | 项目核心逻辑。先写伪代码，再自己写 C++，即使第一次编译失败也保留并分析。 |
| **需要理解，可参考** | CMake、package.xml、plugin XML、YAML 等样板；要能解释其作用，不要求死记格式。 |
| **不需要手写** | Nav2 内部实现、xtensor 底层、ROS 自动生成代码。会使用、会查文档即可。 |

每一步完成前都做四件事：写下输入/输出、写伪代码、亲自编译并保留第一个错误、用自己的话回答“为什么这样设计”。我会先审你的 diff 和报错、给提示；只有你尝试后仍卡住，才给参考实现。
