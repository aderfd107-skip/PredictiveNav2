# 14：观察减速、等待、绕行

> 本步目标：在固定相对运动场景中，判断动态风险是否带来可解释的提前避让，而不是只看机器人最终有没有到达。

## 至少准备三种场景

| 场景 | 风险来源 | 观察重点 |
|---|---|---|
| 横穿自车路径 | 未来同一时刻接近 | 是否提前减速，最小距离是否增加 |
| 对向接近 | TTC 快速变小 | 是否避免贴近、振荡或异常角速度 |
| 窄通道阻塞 | 局部绕行空间很少 | 等待、绕行、恢复还是卡死 |

先从中央开阔区域横穿开始。窄 L 型通道会把地图通行性、footprint、静态 costmap、局部
控制与预测误差混在一起，不适合作为第一条动态风险证据。

## 每一次 run 应记录什么

```markdown
### Run <编号>
- 日期 / git revision：
- controller：baseline / dynamic-risk
- 起点 → 目标：
- actor 路线、速度、循环方式：
- prediction 是否新鲜：
- 结果：reached / aborted / timeout
- 最小动态距离：
- 机器人行为：直行 / 减速 / 等待 / 绕行 / recovery
- DynamicRiskCritic 的最大 cost 或诊断：
- 下一次只改的一项：
```

保存 rosbag、终端日志和截图之一。AI 可以协助整理记录，但结论必须能追溯到原始证据。

## 怎样判断 prediction 真正起作用

最终没撞并不足够。至少应同时看到以下两项：

1. actor 接近时 Critic 的 dynamic cost 上升；
2. 与同一时序的 baseline 相比，机器人在冲突**之前**出现可解释动作；
3. 最小距离、近碰次数或到达率至少一项改善，并且不是靠无限停车换取安全。

## 等待和绕行哪个更合理

| 条件 | 更合理的行为 |
|---|---|
| 方块很快离开、旁边空间不够 | 减速或等待 |
| 旁边有足够无碰撞空间、全局方向允许 | 局部绕行 |
| 通道物理上过窄 | 停止或 recovery，不应“挤墙通过” |

机器人停住不自动表示 Critic 正确；可能是所有候选碰撞、TF/AMCL 异常、action 已终止或
外层 safety guard 限速。必须结合 Critic 日志和 `/cmd_vel` 判断。
