# 14：观察减速、等待、绕行

> **本步目标：** 在横穿、对向和窄通道三类固定场景中，观察动态风险是否使机器人合理减速、等待或绕行。
>
> **AI 会做什么：** 生成实验命令、记录模板和初步分析；根据你的日志、截图或 rosbag 填写 run 记录。
>
> **你只需要做到：** 判断行为是合理避让、代价过高导致的犹豫，还是感知/预测/控制链路错误。

让机器人与动态方块在不同相对位置相遇，观察自定义风险是否促使它减速、等待或选择更安全的局部动作。

不要只看“它动了没有”；要同时记录目标、初始位置、方块路线、最小距离和导航结果。

完成标准：至少得到一个成功避险案例和一个需要继续调参的失败案例。

## 本步：AI 生成实验材料，你提供并核验事实

不要求新增大段 C++。让 AI 生成实验场景表、运行命令、日志模板和失败分析草稿；你实际运行案例、保存日志/截图，并核对 AI 的结论没有脱离证据。如果观察暴露算法缺陷，再让 AI 修改风险逻辑，并重复验证。

## 至少准备三种场景

| 场景 | 预期风险 | 你要记录什么 |
|---|---|---|
| 横穿自车路径 | 未来同一时刻接近 | 是否提前减速、最小距离、是否到达 |
| 对向接近 | TTC 变小 | 是否避免贴近/振荡、角速度是否异常 |
| 窄通道阻塞 | 绕行代价高 | 是等待、绕行还是错误卡死 |

每次记录：地图版本、起点、目标、actor 路线/速度、YAML git revision、是否启用 safety guard、结果、最小距离和失败原因。AI 可以整理记录，但原始日志和截图必须保留。

## 观察时必须分清

- 机器人停住，不自动等于 DynamicRiskCritic 正确：可能是 MPPI 无可行轨迹、AMCL/TF 异常、action 失败或 scan safety guard 限速；
- 机器人绕开，也不自动等于 prediction 生效：可能是静态 costmap 已经看到了当前障碍；
- 必须检查 Critic 日志/统计，确认危险候选的动态 cost 确实升高。

这一页未来会成为第 05 模块实验表的原始证据，不要只保存最好看的一次截图。

## 每次实验都保存证据，不要凭记忆回看视频

让 AI 在 `docs/` 下创建并维护实验日志，例如 `docs/mppi_dynamic_risk_runs.md`。每跑一次，将终端输出、截图或 bag 路径交给 AI，由它填入下面模板；你在保存前核对内容：

```markdown
### Run <编号>
- 日期 / git commit：
- controller 配置：baseline / dynamic-risk
- 起点 → 目标：
- actor 名称、路线、速度：
- prediction 是否新鲜：
- 结果：reached / aborted / timeout
- 最小动态距离：
- 机器人采取的动作：直行 / 减速 / 等待 / 绕行 / recovery
- Critic 日志中最大的 dynamic cost：
- 失败原因或下一次只改的一项：
```

先从中央开阔区域的横穿场景开始，不要直接用最窄的 L 型出口。窄通道会把地图通行性、局部代价地图、DWB/MPPI 控制和动态预测混在一起，不能作为第一条动态风险证据。

### 怎样判断“预测真的产生了作用”

至少同时满足两项才算：

1. Critic 日志显示接近时段的动态 cost 高于远离时段；
2. 与原版 MPPI 的相同 actor 时序相比，机器人在冲突前就出现可解释的减速/等待/绕行；
3. 最小距离、近碰或到达率至少有一项改善，且没有靠无限停车换取安全。

只有“最终没撞”并不能证明是预测造成的。
