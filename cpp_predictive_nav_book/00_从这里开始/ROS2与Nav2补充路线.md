# ROS 2 与 Nav2：跟着 PredictiveNav2 补，不单独硬学

## 这份路线的使用方式

你不需要暂停项目，再花几周从头刷完 ROS 2 或 Nav2 教程。

正确顺序是：**先在项目中遇到一个真实问题，再补足刚好解决它的知识。** 例如，第 06 步需要把激光点转换到 `odom`，这时再理解 TF、坐标系和时间戳；没有这个真实问题，单独背 TF 概念很容易忘。

每个小章末尾都有两栏：

- **本章必须懂**：必须能用自己的话解释，且能通过本章运行结果验证；
- **可选扩展**：现在知道名字和用途即可。不懂不阻塞当前项目，也不要求立刻看教程。

这不是额外的练习清单，更不是要求你从零手写代码。它只是告诉你：此刻写的代码背后，哪一个 ROS 2 / 导航概念值得顺手弄懂。

## 第 01 模块：LiDAR 到障碍物观测

| 小步骤 | 本章必须懂 | 可选扩展（暂不要求） |
| --- | --- | --- |
| 00 输入输出 | `/scan` 是一条 ROS 2 topic；`LaserScan` 是它承载的消息 | topic、service、action 的完整区别 |
| 01 观察 scan | `header.frame_id` 表示数据所在坐标系；`header.stamp` 表示测量时刻；仿真时间与墙钟时间不同 | ROS 2 clock 的完整实现 |
| 02 创建包 | `package.xml` 写依赖，`CMakeLists.txt` 写怎样构建，`source install/setup.bash` 让新包可被 ROS 2 找到 | ament 的高级导出规则、工作空间 overlay |
| 03 订阅 scan | 节点、订阅者、回调函数；为什么激光传感器使用 `SensorDataQoS` | executor、callback group、多线程 spin |
| 04 筛选距离 | `range_min/max` 是传感器消息自身的有效范围；`NaN` / `Inf` 不是可用测量 | QoS 的 reliability / durability 全部组合 |
| 05 变为二维点 | `angle_min + i * angle_increment` 确定第 `i` 束方向；点此时仍在 `lidar_link` | 三维点云、PCL |
| 06 转到 odom | TF 是坐标系之间、带时间的信息；必须按 scan 的原始时间戳查询 `odom ← lidar_link` | `map` 与 `odom` 的定位融合细节、tf2 的缓存实现 |
| 07 聚类 | cluster 只是“几何上一团相邻点”，还不是“动态障碍物”；动态性必须靠跨帧跟踪判断 | DBSCAN、栅格地图、点云分割 |
| 08 发布观测 | 消息定义、发布者、接口包；下游模块不能依赖 Gazebo 真值 | DDS、消息序列化细节 |
| 09 RViz 验证 | RViz 是调试可视化工具；rosbag 用来记录和复现问题 | Foxglove、自动化回放测试 |

## 后续模块：知识会在什么时候出现

### 第 02 模块：多目标跟踪

项目重点是“这一帧的 cluster 和上一帧哪一个是同一个障碍物”。ROS 2 只需补：消息时间戳、发布订阅的数据流和 rosbag 回放。真正需要重点理解的是算法：最近邻关联、轨迹 ID、匀速模型，以及为什么可能发生 ID 切换。

现在不需要提前学 Nav2。

### 第 03 模块：轨迹预测

重点变为卡尔曼滤波、状态向量、协方差和预测时间窗。ROS 2 的新内容不多；你主要要保证预测结果带有正确的 frame 和时间语义。

### 第 04 模块：MPPI 动态风险避障

这时才集中补 Nav2，顺序如下：

1. 先分清全局 planner、局部 controller、costmap 和行为树各自的职责；
2. 再理解 MPPI 会生成许多机器人候选轨迹，并由多个 critic 分别打分；
3. 最后学习 `pluginlib`、Nav2 lifecycle node 和参数配置，编写你的动态风险 critic。

你不需要重写 Nav2，也不需要一开始就看完所有 controller。你只要能说清：你的 critic 输入了什么预测信息、怎样对一条候选机器人轨迹计算风险、它如何与原有 critic 的分数合在一起。

### 第 05 模块：实验验证与项目表达

这里补 rosbag、参数文件、可复现 launch、日志和结果指标。它们会让你能拿数据证明：加入动态风险后，碰撞率、最小障碍物距离、到达时间或路径长度发生了什么变化。

## 一个判断标准

学完一个概念，不以“背出定义”为标准，而以能回答下面三件事为标准：

1. 它在我当前这段代码里解决什么问题？
2. 不使用它会出现什么可观察的错误或限制？
3. 我用哪条命令、哪行日志或哪个 RViz 画面验证它真的工作？

能回答这三件事，就已经是对项目真正有用的掌握；后续再逐步补算法横向对比即可。
