# PredictiveNav2：跟着真实项目学 C++

这里不是一门先讲完语法、再开始项目的传统 C++ 课。

这里的主线是：**项目下一步需要什么，就完成一个很小、可运行、可验证的步骤；该步骤出现什么 C++，就只学习那部分 C++。**

你现在不用独立从空白写代码。每一步都会按以下顺序进行：

```text
我先说明这一步为什么属于项目
→ 给出完整、可运行的代码和明确文件位置
→ 你复制命令运行，观察结果
→ 我把新增代码逐段解释
→ 你只改一个已经标明的位置，再观察变化
→ 我们确认这一小步成功后才进入下一步
```

## 从哪里开始

直接进入 [第一模块：LiDAR 到动态障碍物观测](01_LiDAR到动态障碍物观测/README.md)。这是 PredictiveNav2 当前真正缺少的第一个功能，不会先绕去学习脱离项目的语法。

ROS 2 和 Nav2 也不单独开一门“先学完再做项目”的课。请把 [ROS2与Nav2补充路线](00_从这里开始/ROS2与Nav2补充路线.md) 当成随用随查的导航：每一小章只补本章必需的概念，后续算法再逐步横向扩展。

## 模块路线

| 模块 | 项目会新增什么能力 | 会自然遇到的 C++ |
| --- | --- | --- |
| 01 LiDAR 到动态障碍物观测 | 机器人从 `/scan` 得到障碍物 cluster | ROS 2 C++ 节点、回调、`vector`、函数、类、参数 |
| [02 多目标跟踪](02_多目标跟踪/README.md) | 持续为障碍物维护 ID、位置和速度 | 数据结构、对象生命周期、关联逻辑、Eigen、单元测试 |
| 03 轨迹预测 | 预测未来位置与不确定性 | Eigen、矩阵、卡尔曼滤波、封装 |
| 04 MPPI 动态风险避障 | 候选路径会评估动态障碍物风险 | pluginlib、继承、生命周期、线程安全缓存 |
| 05 实验验证与项目表达 | 可复现实验和可解释结果 | 文件输出、测试、调试与工程整理 |

## 第一模块的最终效果

完成第一模块后，数据流会由目前的：

```text
Gazebo → /scan → （还没有自定义 C++ 感知算法）
```

变成：

```text
Gazebo → /scan → predictive_nav_perception（你的 C++ 节点）
                → /dynamic_obstacles/clusters
                → RViz 中可见的障碍物观测
```
