# 00：这一模块要做什么

## 最终输入和输出

输入来自已经存在的 LiDAR 话题：

```text
/scan   类型：sensor_msgs/msg/LaserScan
```

它包含许多距离值：例如激光向前方、左前方、右方各测到多远。它不知道哪里是一个完整障碍物。

本模块最终要发布：

```text
/dynamic_obstacles/clusters
```

其中每个 cluster 是一组很靠近的激光点，例如“这个方块左边缘到右边缘的多个点”。我们会从它算出中心位置、宽高和点数。

## 为什么这是动态导航的第一步

后面的跟踪模块无法直接处理几百个散乱激光点；它需要的是“本时刻观测到 3 个物体，各自在哪里”。因此，聚类是以后 ID、速度、轨迹预测和风险避障的地基。

## 这一步不会做什么

- 不读取 Gazebo 动态 actor 的真值 Marker；
- 不估计速度，不预测未来；
- 不修改 Nav2 或 `/cmd_vel`；
- 不把静态障碍物神奇地全部删除。

先做到“根据真实 `/scan` 稳定产生几何观测”就已经是一个完整、重要的项目阶段。

## 本章关联的 ROS 2 知识

**本章必须懂**：`/scan` 是一个不断发布的 topic，`sensor_msgs/msg/LaserScan` 是每一帧数据的格式。现在只需理解“谁发布、谁订阅、数据最终要流向哪里”。

**可选扩展**：service 和 action 先不学；它们会在后续向 Nav2 发送导航目标时自然出现。
