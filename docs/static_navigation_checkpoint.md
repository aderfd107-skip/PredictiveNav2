# 静态安全导航检查点（2026-09-21）

本文件记录动态障碍物实验开始前的**真实项目状态**。它既是后续回归测试的基准，也可直接作为面试复习材料。

## 1. 这一阶段完成了什么

项目已经完成从 RViz 点击目标到 Gazebo 圆形差速车执行的静态导航闭环：

```text
RViz 2D Goal Pose
  → /corner_alignment/goal
  → corner_alignment_goal_bridge
  → ComputePathToPose（全局路径）
  → 自动插入拐角预对齐/退出航点
  → NavigateToPose / DWB
  → /cmd_vel
  → scan_safety_guard
  → /cmd_vel_safe
  → ROS-Gazebo bridge → DiffDrive → odom / TF / scan
```

关键配置：

| 项目 | 当前值/事实 | 意义 |
|---|---|---|
| 小车模型 | 圆形底盘，物理半径约 `0.110 m` | 与计划真机底盘形式一致；碰撞不依赖“长方体车壳”侥幸通过。 |
| Nav2 `robot_radius` | `0.135 m` | 含仿真裕量的规划半径；不得为了通过窄道而缩小。 |
| 地图与 costmap 分辨率 | `0.025 m` | 使用 SDF 墙体派生的真值地图，降低由 SLAM 栅格误差造成的混淆。 |
| `inflation_radius` | `0.42 m` | 保持安全缓冲，不为提高通过率而降低。 |
| DWB `PathDist.scale` | `32.0` | 曾降低到 `16.0`，虽更愿意前进却发生撞墙，因此恢复。 |
| 最终安全闸门 | 全向 `0.16 m`、前后向 `0.20 m` | 接近墙体时阻止平移；圆形底盘原地转向不受阻。 |

## 2. 已验证的能力

- `map → odom → base_footprint` TF 链、AMCL、Gazebo 时钟、/scan、/odom、Nav2 lifecycle 均可稳定启动。
- 机器人可在普通开阔静态区域接收 RViz 目标、规划并完成导航。
- bridge 能从全局路径识别明显转角，依次执行“进入前对齐、转角后退出、最终目标”；这减少了贴着内侧凸角一边前进一边转弯的情况。
- bridge 支持目标抢占：用户再次点击目标时，先取消当前 `NavigateToPose` 小段，再从当前位置重新规划，不允许两条任务同时控制机器人。
- DWB 评分可借助 `/evaluation` 与 `dwb_evaluation_monitor.py` 排查；能够区分“所有前进候选碰撞”和“前进候选存在但原地转向评分更低”。
- 安全闸门已经观察到实际效果：Nav2 曾发布 `/cmd_vel` 的 `linear.x=0.35 m/s`，而 `/cmd_vel_safe` 被过滤为零。这说明不会再把 Gazebo 中的实体挤墙误判成一次成功导航。

## 3. 窄 L 型出口：结论必须如实表述

出口宽约 `0.44 m`，规划直径为 `2 × 0.135 = 0.27 m`。若严格居中，理论余量为：

```text
(0.44 - 0.27) / 2 = 0.085 m / side
```

因此它不是绝对物理不可通行，但属于对位姿、局部轨迹和控制误差都非常敏感的苛刻 L 型窄角。

当前普通 DWB 可能在此处选择原地转向，也可能在接近墙面时被最终安全闸门停止。过去曾出现“物理接触后沿墙滑动、最终仍到达目标”的现象；这**不能**记为成功，因为真机上可能造成蹭墙、打滑或驱动过载。

当前正确结论：

> 已完成静态安全导航基线；尚未实现无碰撞自主穿越该窄 L 型出口。当前系统会安全拒绝硬挤，而不是伪造通过率。

这不是项目失败，而是后续 MPPI / 自定义局部规划与通道可行性判定的明确改进目标。

## 4. 为什么此时进入动态障碍物阶段

动态实验首先选择**中央开阔区**，不叠加窄通道。这样可以单独验证：

```text
动态 actor 运动
  → LiDAR cluster
  → Track（CV Kalman）
  → 未来轨迹与协方差
  → 预测风险评价 / 局部规划行为
```

若一开始混合动态障碍物与窄 L 型出口，机器人停下时无法判断根因是：目标预测错误、局部规划评分、传感器遮挡、静态几何还是通道本身过窄。

## 5. 面试怎么讲

### 60 秒版本

> 我先搭建了 ROS 2 Jazzy、Gazebo Harmonic 和 Nav2 的静态安全基线。机器人是圆形差速底盘，使用 2D LiDAR、AMCL 和 DWB；地图由 Gazebo SDF 墙体自动生成，costmap 分辨率为 2.5 厘米。针对 L 型窄角中 DWB 容易边走边转、贴内侧墙的问题，我在 Nav2 上层实现了一个 Python 行为编排器：它分析全局路径，在显著拐角前插入朝向下一段的预对齐点，并支持新目标抢占后从当前位置重规划。重要的是，我没有通过缩小机器人半径或降低通胀层来硬提高通过率；我在 `/cmd_vel` 与 DiffDrive 之间保留了激光最终安全闸门。实验中发现某条 0.44 米窄 L 型通道会出现安全拒绝，因此我如实记录为当前 DWB 的局限，并把它留作后续预测风险 MPPI 的高难度对照场景。接下来我会先在开阔区独立验证动态目标检测、跟踪、预测和规划耦合。

### 常见追问

**为什么“到了目标”仍不算成功？**

因为 Gazebo 的刚体接触会让差速驱动沿墙滑动；它不能证明轨迹无碰撞。成功标准必须包含无实体碰撞、足够余量、低恢复次数和到达目标。

**为什么不直接缩小 `robot_radius`？**

它代表真实机械外廓加安全余量。缩小会让 costmap 接受真机无法安全通过的轨迹，得到虚假的通过率。

**拐角预对齐器和 DWB 的边界是什么？**

预对齐器是任务级行为编排：它只发送分段 `NavigateToPose` 目标，不发布速度，也不取代 DWB。DWB 仍负责每一小段的局部碰撞检查与速度选择。

**为什么还需要 MPPI 或自定义 critic？**

DWB 的短预测与离散 critic 在复杂窄角和动态交互中可能偏向原地转向或局部最优。后续 MPPI 可以在一段控制序列上采样优化；自定义动态风险 critic 则把预测目标的位置、速度和协方差转为轨迹风险，而不是仅依据当前激光点避障。
