# 2. 第一个 C++ 节点：扫描诊断

> 这一章是第一个编码里程碑。完成后你会拥有自己的 C++ ROS 2 package；它虽然只做“统计”，却是以后所有动态障碍物算法的可靠输入边界。

## 2.1 本阶段要完成什么

创建 package `predictive_nav_perception` 和可执行节点 `scan_diagnostics_node`。节点订阅 `/scan`，对每一帧统计：

- 总激光束数量。
- 有效距离数量。
- 非有限值数量（NaN 与 Inf）。
- 有限但在 `range_min`、`range_max` 之外的数量。

每隔几秒打印一次汇总，而不是每帧疯狂刷屏。**本章不做坐标变换、不做聚类、不判断动态性。**

## 2.2 为什么看似简单的步骤不能跳过

一帧 `LaserScan` 不是“全部都是障碍物点”的数组：

- `NaN` 表示无法使用的数值。
- `+Inf` 通常表示该方向未测到量程内回波。
- 太近/太远的数值不适合后续几何计算。
- 以后 TF 可能短暂不可用，时间戳也可能异常。

感知节点的原则是：**坏输入应被安全丢弃和计数，而不是导致崩溃、生成假障碍物或静默掩盖问题。**

## 2.3 本章所需的最小 C++ 知识

### 头文件与源文件

`.hpp` 放“别人需要知道的声明”；`.cpp` 放“具体实现”。例如：

```cpp
// range_validation.hpp：告诉其他 .cpp 有这个函数和这个结构体
struct ScanStatistics {
  std::size_t total{0};
  std::size_t valid{0};
};

ScanStatistics summarize_ranges(const sensor_msgs::msg::LaserScan & scan);
```

```cpp
// range_validation.cpp：真正写循环和判断
ScanStatistics summarize_ranges(const sensor_msgs::msg::LaserScan & scan) {
  // ...
}
```

头文件末尾不会写完整实现，避免多个 `.cpp` 同时包含时产生“重复定义”。`#pragma once` 的作用是防止同一头文件被重复包含。

### `const T&`：本项目最常见的参数形式

```cpp
ScanStatistics summarize_ranges(const LaserScan & scan);
```

- `T`：按值传递，会复制一整个对象；对小整数可以，对整帧 scan 不合适。
- `T&`：引用传递，不复制，可修改原对象。
- `const T&`：引用传递，不复制，**并明确函数不允许修改输入**。

因此，读取 ROS 消息或点数组时通常使用 `const T&`。这比 C 中传 `const struct Xxx *` 更安全直观：调用者不需检查 `nullptr`，函数也不能修改输入。

### `std::size_t`、范围 for 和花括号初始化

```cpp
std::size_t count{0};             // 用于数组大小/索引的无符号类型
for (const float range : scan.ranges) {
  // range 是当前元素的一个副本；float 很小，这样写没问题
}
```

`{0}` 这种花括号初始化在 C++ 中推荐使用：不会发生悄悄的窄化转换。

### `std::shared_ptr` 不等于“你负责 free”

ROS 2 订阅回调常收到：

```cpp
sensor_msgs::msg::LaserScan::ConstSharedPtr msg
```

它是“共享所有权的只读消息指针”。你只读 `msg->ranges`，回调结束后让 ROS 2 自动管理生命周期；**不需要也绝不能 `delete msg`**。`msg->x` 是指针访问成员，等价于 `(*msg).x`。

### `std::isfinite`

浮点数除了普通数值，还能表示 NaN 与 Infinity。任何要进入坐标、矩阵或距离计算的 range，都应首先经过：

```cpp
if (!std::isfinite(range)) {
  // 丢弃并计数
}
```

要使用它，包含 `<cmath>`。

## 2.5 先写不依赖 ROS 运行时的核心函数

先创建 `include/predictive_nav_perception/range_validation.hpp`：

```cpp
#pragma once

#include <cstddef>

#include <sensor_msgs/msg/laser_scan.hpp>

namespace predictive_nav_perception
{

struct ScanStatistics
{
  std::size_t total{0};
  std::size_t valid{0};
  std::size_t non_finite{0};
  std::size_t outside_sensor_limits{0};
};

ScanStatistics summarize_ranges(const sensor_msgs::msg::LaserScan & scan);

}  // namespace predictive_nav_perception
```

然后自己尝试完成 `src/range_validation.cpp`。算法只有四步：

```text
stats.total = scan.ranges.size()
遍历每个 range：
  若非有限：non_finite++，继续下一条
  若 range < range_min 或 range > range_max：outside_sensor_limits++，继续
  否则：valid++
返回 stats
```

完成后可对照下面的参考实现。先遮住它自己写一遍。

```cpp
#include "predictive_nav_perception/range_validation.hpp"

#include <cmath>
#include <limits>

namespace predictive_nav_perception
{

ScanStatistics summarize_ranges(const sensor_msgs::msg::LaserScan & scan)
{
  ScanStatistics stats;
  stats.total = scan.ranges.size();

  for (const float range : scan.ranges) {
    if (!std::isfinite(range)) {
      ++stats.non_finite;
      continue;
    }

    if (range < scan.range_min || range > scan.range_max) {
      ++stats.outside_sensor_limits;
      continue;
    }

    ++stats.valid;
  }

  return stats;
}

}  // namespace predictive_nav_perception
```

### 逐行理解关键部分

- `ScanStatistics stats;`：在栈上创建局部对象；函数返回后由值返回，现代 C++ 会优化，不必手动释放。
- `continue;`：本次循环结束，直接检查下一束激光。这样无效数据不会落入“有效”分支。
- `range_min`、`range_max` 来自**每一帧消息**，不能写死为某个猜测值。
- 范围边界采用 `<=` 意义上的有效：等于 `range_min/max` 允许通过；因此只排除 `<` 和 `>`。

## 2.6 先为核心函数写测试

测试不需要启动 Gazebo。创建 `test/test_range_validation.cpp`：

```cpp
#include "predictive_nav_perception/range_validation.hpp"

#include <cmath>
#include <limits>

#include <gtest/gtest.h>

TEST(SummarizeRanges, CountsValidAndInvalidRanges)
{
  sensor_msgs::msg::LaserScan scan;
  scan.range_min = 0.10F;
  scan.range_max = 10.00F;
  scan.ranges = {
    0.10F, 5.00F, 0.05F, 11.00F,
    std::numeric_limits<float>::infinity(),
    std::numeric_limits<float>::quiet_NaN()};

  const auto stats = predictive_nav_perception::summarize_ranges(scan);

  EXPECT_EQ(stats.total, 6U);
  EXPECT_EQ(stats.valid, 2U);
  EXPECT_EQ(stats.outside_sensor_limits, 2U);
  EXPECT_EQ(stats.non_finite, 2U);
}
```

`TEST(测试组名, 测试名)` 是 gtest 定义测试的方式；`EXPECT_EQ` 即使失败也会继续执行本测试，适合一次报告多项检查。

再至少补两个你自己设计的测试：空 `ranges`；等于 `range_max` 的数值。写测试的顺序应该是“思考期望行为 → 写断言 → 写/修改实现”，而不是只为让当前实现通过而写。

## 2.7 写 ROS 2 节点

`src/scan_diagnostics_node.cpp` 的任务是调用上面的纯函数，并使用 ROS 2 订阅和日志。先理解结构：

```text
ScanDiagnosticsNode 继承 rclcpp::Node
  构造函数：声明参数；创建订阅者
  回调 on_scan：调用 summarize_ranges；节流输出日志
main：初始化 ROS → 创建 node → spin → shutdown
```

下面是可运行的参考实现。请先至少自己写出类定义、订阅主题和回调签名。

```cpp
#include <functional>
#include <memory>
#include <string>

#include <rclcpp/rclcpp.hpp>
#include <sensor_msgs/msg/laser_scan.hpp>

#include "predictive_nav_perception/range_validation.hpp"

namespace predictive_nav_perception
{

class ScanDiagnosticsNode : public rclcpp::Node
{
public:
  ScanDiagnosticsNode()
  : Node("scan_diagnostics_node")
  {
    const auto scan_topic = declare_parameter<std::string>("scan_topic", "/scan");
    const auto log_period_s = declare_parameter<double>("log_period_s", 2.0);
    log_period_ms_ = static_cast<int>(log_period_s * 1000.0);

    scan_subscription_ = create_subscription<sensor_msgs::msg::LaserScan>(
      scan_topic,
      rclcpp::SensorDataQoS(),
      std::bind(&ScanDiagnosticsNode::on_scan, this, std::placeholders::_1));

    RCLCPP_INFO(get_logger(), "Listening for LaserScan on '%s'", scan_topic.c_str());
  }

private:
  void on_scan(const sensor_msgs::msg::LaserScan::ConstSharedPtr msg)
  {
    const auto stats = summarize_ranges(*msg);
    RCLCPP_INFO_THROTTLE(
      get_logger(), *get_clock(), log_period_ms_,
      "scan frame='%s': total=%zu valid=%zu non_finite=%zu outside_limits=%zu",
      msg->header.frame_id.c_str(), stats.total, stats.valid, stats.non_finite,
      stats.outside_sensor_limits);
  }

  int log_period_ms_{2000};
  rclcpp::Subscription<sensor_msgs::msg::LaserScan>::SharedPtr scan_subscription_;
};

}  // namespace predictive_nav_perception

int main(int argc, char * argv[])
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<predictive_nav_perception::ScanDiagnosticsNode>());
  rclcpp::shutdown();
  return 0;
}
```

需要理解的地方：

- `Node("scan_diagnostics_node")` 给 ROS graph 中的节点命名。
- `declare_parameter` 既读取又声明参数；第二个值是默认值。
- `SensorDataQoS()` 适合传感器：偏向接收最新数据，宁可偶尔丢帧也不积压过期 scan。
- `std::bind(..., this, std::placeholders::_1)` 告诉订阅者“消息到来时调用这个对象的 `on_scan`”。第 3 章会介绍 lambda 替代写法。
- `*msg` 将 shared pointer 解引用为只读 `LaserScan` 对象，传给 `const LaserScan&` 函数。
- `RCLCPP_INFO_THROTTLE` 的周期单位是毫秒；普通 `RCLCPP_INFO` 会以约 10 Hz 打印，干扰调试。

## 2.8 CMakeLists.txt 与 package.xml

将 `CMakeLists.txt` 改成下面的完整最小版本：

```cmake
cmake_minimum_required(VERSION 3.8)
project(predictive_nav_perception)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

if(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
  add_compile_options(-Wall -Wextra -Wpedantic)
endif()

find_package(ament_cmake REQUIRED)
find_package(rclcpp REQUIRED)
find_package(sensor_msgs REQUIRED)

add_library(range_validation src/range_validation.cpp)
target_include_directories(range_validation PUBLIC
  $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
  $<INSTALL_INTERFACE:include>)
ament_target_dependencies(range_validation sensor_msgs)

add_executable(scan_diagnostics_node src/scan_diagnostics_node.cpp)
target_link_libraries(scan_diagnostics_node range_validation)
ament_target_dependencies(scan_diagnostics_node rclcpp sensor_msgs)

install(TARGETS range_validation scan_diagnostics_node
  DESTINATION lib/${PROJECT_NAME})
install(DIRECTORY include/
  DESTINATION include)

if(BUILD_TESTING)
  find_package(ament_cmake_gtest REQUIRED)
  ament_add_gtest(test_range_validation test/test_range_validation.cpp)
  target_link_libraries(test_range_validation range_validation)
endif()

ament_package()
```

将 `package.xml` 中至少确认以下依赖存在：

```xml
<buildtool_depend>ament_cmake</buildtool_depend>
<depend>rclcpp</depend>
<depend>sensor_msgs</depend>
<test_depend>ament_cmake_gtest</test_depend>
```

`CMakeLists.txt` 决定“如何编译和安装”；`package.xml` 告诉 ROS 2 这个包依赖哪些 package。两者都必须更新，缺一个都会在构建或运行时出问题。

```text
[INFO] [scan_diagnostics_node]: scan frame='lidar_link': total=... valid=... non_finite=... outside_limits=...
```

数值会随场景和传感器配置变化；不要把某个具体数量作为唯一正确答案。正确性来自：总数稳定、`valid + non_finite + outside_limits == total`，节点持续运行且不崩溃。

## 2.10 高频报错清单

| 报错/现象 | 原因 | 修复方向 |
| --- | --- | --- |
| `fatal error: ...range_validation.hpp: No such file` | 头文件目录未用 `target_include_directories` 暴露 | 检查 `include/predictive_nav_perception/` 路径和 CMake。 |
| `undefined reference to summarize_ranges` | 声明存在但 `.cpp` 没有编入 library，或 node 未链接 library | 检查 `add_library`、`target_link_libraries`。 |
| `Package ... not found` | 新终端没 `source install/setup.bash` | 每次 build 后重新 source。 |
| 节点启动但一直没有日志 | `/scan` 不存在、topic 参数错误、仿真没启动 | `ros2 topic info /scan -v`；检查 `scan_topic` 参数。 |
| 时间停在 0 或 throttle 不输出 | 仿真时钟没启用 | 节点加 `-p use_sim_time:=true`，并确认 `/clock` 存在。 |
| 编译提示 `numeric_limits` 未声明 | 缺头文件 | 测试文件加入 `#include <limits>`。 |
