# 0. 项目路线与学习方法

> 这不是一门脱离项目的 C++ 课。本手册的唯一目标，是让从未学过 C++ 的你能独立完成、解释和展示 PredictiveNav2。

## 0.1 最终要完成什么

项目要解决的问题可以用一句话说清：**机器人只使用 2D LiDAR、TF 和里程计发现移动障碍物，估计它们的运动和不确定性，并把预测结果交给 Nav2 MPPI，使机器人更早、更安全地避让。**

最终运行链路如下。你不需要从零实现 ROS 2、Gazebo 或 Nav2；你要实现的是图中加粗的五段算法/工程连接。

```text
Gazebo 动态 actor
       │              （actor 只是仿真中的运动目标，不是算法输入）
       ▼
2D LiDAR /scan ──> **感知与聚类** ──> **多目标跟踪**
                                              │
                         /odom + TF ─────────┤
                                              ▼
                                        **轨迹预测**
                                              ▼
                                     **DynamicRiskCritic**
                                              ▼
Nav2：地图、定位、全局规划、MPPI ───────> /cmd_vel ───────> Gazebo 机器人
                                              │
                                              ▼
                                        **Benchmark**
```

### 已经存在的能力

- `predictive_nav_description`：差速机器人模型、LiDAR、IMU 与 TF。
- `predictive_nav_simulation`：Gazebo 场景、根话题 `/scan` `/odom` `/tf`、三个可控动态 actor。
- `predictive_nav_bringup`：AMCL + DWB 的已知地图导航对照组。
- `/dynamic_obstacle/ground_truth_marker`：Gazebo actor 的真值可视化，仅用于调试。

### 你将实现的能力

| 里程碑 | 新 package | 输入 | 输出 | 你真正掌握的能力 |
| --- | --- | --- | --- | --- |
| 动态检测 | `predictive_nav_perception` | `/scan` + TF | clusters | C++ ROS 2 节点、激光处理、聚类 |
| 多目标跟踪 | `predictive_nav_tracking` | clusters | tracks | Eigen、卡尔曼滤波、数据关联 |
| 轨迹预测 | `predictive_nav_prediction` | tracks | predictions | 协方差传播、时间语义 |
| 风险控制 | `predictive_nav_mppi` | predictions + MPPI 轨迹 | trajectory costs | C++ 插件、并发与性能 |
| 实验评估 | `predictive_nav_benchmark` | 运行中的 ROS 数据 | CSV/图表 | 对照实验与技术表达 |

## 0.2 不需要现在学习的内容

C++ 很大，但你只需掌握本项目会用到的部分。以下内容在完成项目之前都可以不碰：

- 模板元编程、C++20 concepts、协程。
- 手动 `new`/`delete`、内存池、编写 STL 容器。
- 复杂设计模式、多重继承、过度抽象。
- 刷题中的高级数据结构和算法竞赛技巧。
- 深度学习、PCL、DBSCAN、匈牙利算法。首版先采用可解释、可测试的 Euclidean 聚类和最近邻关联。

这不是逃避难点，而是工程上的正确取舍：先做出可重复运行且能解释的最小系统，再以 benchmark 结果决定是否需要增加复杂算法。

## 0.3 你从 C 迁移到 C++ 时必须改变的习惯

| C 中常见做法 | 本项目中的 C++ 做法 | 原因 |
| --- | --- | --- |
| `malloc` / `free` | `std::vector`、栈对象、智能指针 | 自动管理资源，少内存泄漏与悬空指针。 |
| `struct` + 一堆函数 | 小型 `struct` 表示纯数据；`class` 封装有状态算法 | 让 Kalman filter、track 生命周期的约束集中在对象内部。 |
| 裸数组 + 长度参数 | `std::vector<T>` / `std::array<T, N>` | 数据和长度绑定，便于检查。 |
| 全局变量 | Node 的私有成员、参数、明确的消息接口 | ROS 2 多节点下全局状态会难以测试和调试。 |
| 复制大型数组 | 用 `const T&` 只读传递 | 避免无意义拷贝，同时表达“函数不会修改输入”。 |
| 返回错误码后忘记检查 | 返回 `std::optional`，或显式丢帧并计数/记录日志 | 传感器/TF 错误是正常输入，不能让节点崩溃。 |

你不必死记这些规则。第 2–5 章会在真实代码中反复使用它们。

## 0.4 每一章的固定工作方式

每个项目里程碑都遵循相同循环；请不要跳过任何一项。

1. **读目标。** 先理解这一章的输入、输出和完成标准，而不是先复制代码。
2. **学本章的新知识。** 只学实现这一步所需的 C++/ROS 2/数学内容。
3. **写最小离线练习。** 先不接 ROS，例如先把一组 ranges 过滤成有效距离。
4. **接入项目。** 将离线函数放进 package，再接 ROS topic、TF、参数和 Marker。
5. **验证。** 至少包含构建、单元测试、运行时话题检查和 RViz 观察。
6. **记录与提交。** 记录命令、预期/实际结果、发现的问题；Git commit 只包含一个完整的小功能。

### 推荐的单次学习节奏

每次 60–120 分钟即可。建议一次只达成一个微目标：例如“创建 package 并能构建”或“写完无效 range 的单元测试”，不要一次同时改 CMake、消息、算法和 launch。

遇到报错时，按下面顺序排查：

```text
1. 我运行的命令和当前终端是否 source 了 ROS 与 install/setup.bash？
2. 失败属于编译、链接、节点启动、topic/TF，还是算法结果错误？
3. 最小可复现输入是什么？能否先写一个普通 C++ 测试？
4. 日志/完整报错的第一处 ERROR 是什么？
5. 再向我提问，而不是只发“跑不起来”。
```

## 0.5 工具与目录约定

本项目在以下目录工作：

```bash
cd /home/aderfd/PREDICTIVENAV2
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

> 第一次构建前没有 `install/setup.bash` 是正常的；先执行 `colcon build`。

后续新建 C++ package 统一采用：

```text
src/predictive_nav_perception/
├── include/predictive_nav_perception/  # 可复用的 C++ 头文件
├── src/                                # 节点与实现
├── test/                               # gtest 单元测试
├── CMakeLists.txt
└── package.xml
```

遵循命名约定：

- ROS package、topic、参数、源文件：`snake_case`，如 `scan_diagnostics_node.cpp`。
- C++ 类型：`PascalCase`，如 `ScanDiagnosticsNode`、`Point2D`。
- 函数和变量：`snake_case`，如 `count_valid_ranges`。
- 常量：`kPascalCase`，如 `kMinClusterPoints`。
