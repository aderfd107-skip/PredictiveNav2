# 4. 动态障碍物检测与聚类

> 本章是第一个核心算法里程碑：机器人开始从 `/scan` 自己产生障碍物观测。注意术语上的严谨性：一帧激光只能把点分成“物体 cluster”，不能仅靠一帧证明它**正在运动**。真正的动态判定、速度和稳定 ID 要等第 5 章的多帧跟踪完成。

## 4.1 本阶段的输入、输出和范围

```text
输入：第 3 章得到的 odom 坐标系有效激光点
输出：/dynamic_obstacles/clusters (ClusterArray)
每个 cluster：共同 frame/stamp、点数、质心、二维外接尺寸、可选点列表
```

本章只实现以下流程：

```text
预处理后的按 scan 顺序点列
  → 相邻点 Euclidean 分段
  → 过滤过小、过大、过远的候选组
  → 计算 cluster 特征
  → 发布消息与 RViz Marker
```

本章**不**做：

- 为 cluster 分配跨帧 ID。
- 从一帧数据宣称“它是动态的”。
- 估计速度、卡尔曼滤波、未来轨迹。
- 订阅任何 Gazebo ground-truth 话题。
- 上 PCL、DBSCAN、深度学习或全局地图静态掩码。

先做这个简单版本的理由是：它可解释、能用手工点集单元测试，也能先判断 LiDAR 是否能稳定分出 actor。若 benchmark 显示简单分段确实不足，再增加更复杂方法。


### 每个字段为什么存在

| 字段 | 含义 | 以后谁会使用 |
| --- | --- | --- |
| `header` | frame 和 acquisition time | tracking 必须使用相同时间基准。 |
| `point_count` | 此观测由多少激光点组成 | 过滤、置信度与调试。 |
| `centroid` | 该组点的平均位置 | 关联与卡尔曼滤波观测 `z`。 |
| `size` | odom 轴对齐 bounding box 尺寸 | 剔除不合理组，后续风险半径。 |
| `points` | 原始成员点 | 调试、可视化、后续特征；首版可保留。 |

`ClusterArray.header` 与每个 `Cluster.header` 都使用同一个 scan 的 `stamp` 和 `frame_id="odom"`。看似重复，但每个 cluster 独立存在或被录包读取时仍能保持自描述。

## 4.3 Euclidean 聚类是什么

第 3 章的点保留了它们在一帧 LaserScan 中的顺序。对于同一个连续物体，扫描相邻的激光束通常也会击中空间中相近的点；当激光越过物体之间的空隙，两个连续点的距离会突然变大。

因此首版使用“按 scan 顺序的相邻 Euclidean 分段”：

```text
从第一个点开始形成 current_cluster
对每个下一个点：
  distance = hypot(current.x - previous.x, current.y - previous.y)
  若 distance <= tolerance：加入 current_cluster
  否则：结束并保存 current_cluster；以 current 开始新 cluster
循环结束后别忘记保存最后一个 cluster
```

二维欧氏距离为：

\[
d(p,q)=\sqrt{(p_x-q_x)^2+(p_y-q_y)^2}
\]

在 C++ 中可写：

```cpp
const double distance = std::hypot(a.x - b.x, a.y - b.y);
```

### tolerance 为什么不能无限大或无限小

- 太小：同一个 0.45 m 方块表面的点会被切成多个 cluster。
- 太大：相邻的墙、桌腿、不同 actor 会被合并。

初始可使用 `cluster_tolerance_m = 0.18`，但这只是**待实验验证的初始参数**，不是自然定律。较远距离下相邻激光束的空间间隔变大；最终可把阈值设计为 `base_tolerance + range_scale * mean_range`，但先用固定阈值完成可测试版本。

## 4.4 C++ 数据结构与纯算法设计

新建 `include/predictive_nav_perception/clustering.hpp`。不要让它依赖 ROS Node、TF 或 RViz；它只依赖第 3 章的 `Point2D` 与 STL。

```cpp
#pragma once

#include <cstddef>
#include <vector>

#include "predictive_nav_perception/scan_geometry.hpp"

namespace predictive_nav_perception
{

struct Cluster
{
  std::vector<Point2D> points;
  Point2D centroid;
  double size_x{0.0};
  double size_y{0.0};
};

struct ClusteringParameters
{
  double tolerance_m{0.18};
  std::size_t min_points{3};
  std::size_t max_points{100};
  double min_size_m{0.05};
  double max_size_m{1.20};
};

std::vector<Cluster> cluster_ordered_points(
  const std::vector<Point2D> & ordered_points,
  const ClusteringParameters & parameters);

}  // namespace predictive_nav_perception
```

### 为什么 `ClusteringParameters` 是 struct

这些是简单的配置数据，没有需要保护的不变量；放到一个 struct 能避免函数出现一长串不清楚的 `double, int, double...` 参数。节点负责从 ROS 参数创建它，纯算法函数只接收一个普通 C++ struct，所以单元测试不需要 ROS parameter server。

### 算法的建议分解

在 `src/clustering.cpp` 写三个小函数，而不是一大段 callback：

```text
distance(a, b)                 // 计算两点距离
make_cluster(points)           // 计算质心、min/max x/y 和 size
passes_shape_filter(cluster)   // 检查点数与尺寸
cluster_ordered_points(...)    // 只负责编排分段、构造、过滤
```

`make_cluster` 的数学：

\[
c_x = \frac{1}{N}\sum_i x_i,\qquad c_y = \frac{1}{N}\sum_i y_i
\]

```text
size_x = max(x_i) - min(x_i)
size_y = max(y_i) - min(y_i)
```

外接尺寸是当前 odom 轴对齐的 AABB，不是物体真实旋转尺寸。首版用于粗过滤和可视化足够；不要把它误称为精确长宽。

### `cluster_ordered_points` 的伪代码

```text
如果 ordered_points 为空：返回空 vector
如果 tolerance <= 0 或 min_points == 0：抛出/拒绝无效配置（节点启动时验证更好）

current = [第一个点]
for i = 1 到 n-1：
  如果 distance(points[i-1], points[i]) <= tolerance：
      current.push_back(points[i])
  否则：
      candidate = make_cluster(current)
      如果 passes_shape_filter(candidate)：output.push_back(candidate)
      current = [points[i]]

处理最后一个 current（这是初学者最常漏掉的一步）
return output
```

### 参考实现中的关键结构

不要直接复制下面内容；先依照伪代码完成并跑测试，再核对设计。

```cpp
std::vector<Cluster> cluster_ordered_points(
  const std::vector<Point2D> & ordered_points,
  const ClusteringParameters & parameters)
{
  std::vector<Cluster> output;
  if (ordered_points.empty()) {
    return output;
  }

  std::vector<Point2D> current;
  current.push_back(ordered_points.front());

  const auto try_append_cluster = [&]() {
      const Cluster candidate = make_cluster(current);
      if (passes_shape_filter(candidate, parameters)) {
        output.push_back(candidate);
      }
    };

  for (std::size_t i = 1; i < ordered_points.size(); ++i) {
    if (std::hypot(ordered_points[i].x - ordered_points[i - 1].x,
        ordered_points[i].y - ordered_points[i - 1].y) <= parameters.tolerance_m)
    {
      current.push_back(ordered_points[i]);
    } else {
      try_append_cluster();
      current.clear();
      current.push_back(ordered_points[i]);
    }
  }
  try_append_cluster();
  return output;
}
```

这里的 lambda（`[&] { ... }`）是一个就地定义的小函数：`[&]` 表示按引用使用外部的 `current` 和 `output`。如果你觉得 lambda 还陌生，可以先把它写成重复的普通代码；理解正确比炫技更重要。

## 4.5 必须写的单元测试

新建 `test/test_clustering.cpp`。以下不是可选项；它们是你证明算法正确、以后调参不破坏功能的证据。

| 测试 | 输入 | 期望 |
| --- | --- | --- |
| 空输入 | `[]` | 0 个 cluster，不崩溃。 |
| 一个紧密物体 | 4 个相邻点 | 1 个 cluster，正确点数、质心、尺寸。 |
| 两个间隔物体 | 2 组点，中间距离大于 tolerance | 2 个 cluster。 |
| 最后组 | 最后一组没有后续断点 | 最后一个 cluster 仍被输出。 |
| 过少点 | 1–2 点 | 被 `min_points` 过滤。 |
| 过大物体 | 尺寸超过 `max_size_m` | 被过滤。 |
| 边界 | 距离恰好等于 tolerance | 明确规定为同一 cluster（本章使用 `<=`）。 |

一个紧密组测试的思路：点 `(0,0)`、`(0.1,0)`、`(0.1,0.1)`，tolerance 为 `0.2`。检查：

```cpp
ASSERT_EQ(clusters.size(), 1U);
EXPECT_EQ(clusters[0].points.size(), 3U);
EXPECT_NEAR(clusters[0].centroid.x, 0.0666666667, 1e-8);
EXPECT_NEAR(clusters[0].centroid.y, 0.0333333333, 1e-8);
EXPECT_NEAR(clusters[0].size_x, 0.1, 1e-8);
EXPECT_NEAR(clusters[0].size_y, 0.1, 1e-8);
```

## 4.6 把纯算法接到 ROS 2 节点

你有两种合理选择：扩展第 3 章的 `scan_preprocessor_node`，或创建新 `cluster_detector_node`。**本项目选择创建新节点**：感知各阶段的职责清晰，未来可独立录包/重放预处理输出。

但为了不过早定义一个很大的内部点云消息，首版 `cluster_detector_node` 可直接订阅 `/scan` 并复用第 3 章的“过滤 + scan stamp TF”函数。它的内部步骤为：

```text
on_scan(msg)
  1. 使用 msg stamp 查询 odom ← msg.frame_id
  2. scan_to_lidar_points(*msg, extra_min_range_m)
  3. 每点变换到 odom，且保持 scan 顺序
  4. cluster_ordered_points(odom_points, parameters_)
  5. 转换成 ClusterArray，发布 /dynamic_obstacles/clusters
  6. 发布可视化 MarkerArray
```

这样会有一点 scan 预处理代码复用问题。解决方式是将“TF 变换后的点列”提取为 `scan_transformer.hpp/.cpp` 的纯/小型可复用模块，**而不是**复制一份可能逐渐不一致的代码。若这个提取对你现在过难，先复用第 3 章节点的函数，完成后再请我带你做小重构。

### 节点必须有的参数

| 参数 | 推荐初始值 | 用途 |
| --- | --- | --- |
| `scan_topic` | `/scan` | 输入 topic。 |
| `target_frame` | `odom` | 所有输出的 frame。 |
| `extra_min_range_m` | `0.20` | 排除离 LiDAR 过近的点。 |
| `tf_timeout_s` | `0.05` | TF 不可用时最多等待时间。 |
| `cluster_tolerance_m` | `0.18` | 连续点分段阈值。 |
| `min_cluster_points` | `3` | 排除孤立噪声。 |
| `max_cluster_points` | `100` | 排除大面积墙面候选。 |
| `min_cluster_size_m` | `0.05` | 排除近似单点噪声。 |
| `max_cluster_size_m` | `1.20` | 排除明显过大的组。 |

启动时对参数做有效性检查：`tolerance > 0`、`min_points >= 1`、`max_points >= min_points`、尺寸上下界正确。配置错误应在启动时清楚报错，不能运行到一半产生奇怪结果。

### ClusterArray 转换规则

伪代码：

```text
array.header = msg.header，但 array.header.frame_id 改为 target_frame
for each internal Cluster:
  ros_cluster.header = array.header
  ros_cluster.point_count = cluster.points.size()
  ros_cluster.centroid = (centroid.x, centroid.y, z=0)
  ros_cluster.size = (size_x, size_y, z=0)
  把每个 Point2D 转成 geometry_msgs/Point(x, y, 0)
  array.clusters.push_back(ros_cluster)
publish array
```

千万不要把 `ClusterArray` 的 `frame_id` 仍填成 `lidar_link`，但里面实际放 odom 坐标；这种“数据与 header 不一致”的错误会在第 5 章表现为莫名 ID 跳变。

### RViz 可视化建议

发布 `visualization_msgs::msg::MarkerArray`，每个 cluster 至少两个 Marker：

- `CUBE`：中心为 cluster centroid，scale 为 `size_x/size_y`，半透明黄色；用于观察尺寸过滤。
- `TEXT_VIEW_FACING`：显示点数与临时序号；仅调试使用，不能被当作 track ID。

每帧都应先发布上帧残余 Marker 的 `DELETEALL`，再发布本帧 ADD Marker；否则 cluster 消失后 RViz 会残留旧框，误导你以为算法还在跟踪它。

## 4.9 如何调参，而不是凭感觉改数字

一次只改一个参数，固定 actor 路线并记录结果。建议记录：

| 参数 | 值 | actor 可见时 cluster 数量 | 目标 cluster 点数/尺寸 | 误检 | 备注 |
| --- | --- | --- | --- | --- | --- |
| tolerance | 0.18 | | | | 初始值 |
| tolerance | 0.14 | | | | |
| tolerance | 0.22 | | | | |

调参规律：

- 同一 actor 被切成很多段：适度增大 tolerance。
- 不同物体粘在一起：减小 tolerance 或收紧 `max_size_m`。
- 大量孤点：增大 `min_cluster_points`。
- actor 整体被过滤：检查其点数/尺寸，不要盲目放宽所有过滤。

保存选择参数的理由；未来面试时“为什么是 0.18”应回答“通过固定场景扫描结果调参并记录”，而不是“网上看到的”。

## 4.10 常见失败模式

| 现象 | 常见根因 | 正确处理 |
| --- | --- | --- |
| 没有任何 cluster | `min_points` 太大、TF 丢帧、actor 未被 LiDAR 看见 | 先打印预处理点数/TF drop 计数，再检查参数。 |
| 每帧 actor cluster 点数变化 | 激光角分辨率、距离、遮挡造成 | 正常；跟踪章会用滤波和生命周期处理。 |
| 很多墙壁 cluster | 本章尚无静态 map 过滤 | 先记录与尺寸过滤；第 5 章通过运动/轨迹处理，后续可增加静态 mask。 |
| 只看 truth Marker 就得出“检测正确” | 真值与算法数据混淆 | 在 RViz 同时显示，但只从 `/dynamic_obstacles/clusters` 评估算法。 |
| RViz 有旧方框 | 未删除上一帧 Marker | 每帧 DELETEALL 或维护稳定 marker 生命周期。 |
| 用 `std::vector` 里元素的指针长期保存 | 下一帧 `push_back` 重分配后指针失效 | cluster 内保存值或索引；不要跨 callback 保存临时 vector 指针。 |
